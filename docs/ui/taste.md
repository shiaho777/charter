# 品味作为可检查的约束

"美"教不会，但"廉价"几乎总能归约为一小撮违规。每条都有检测方法——在截图上测，不靠感觉。

## 每屏一个焦点

五个东西抢视线 = 眼睛无处安放。精致 = 一个明确焦点，其他安静服务。
**检测**：眯眼看截图（或问"哪个元素最先抓眼？"）。答案不是唯一的、且不是你想要的那个，就是重点错了。

## 层级来自字重字阶，不来自新颜色

每个 section 加一个强调色 = 调色板失控，读起来花。深度来自字号、字重、表面色调。
**检测**：`designAudit` 的 accent-hues——一屏超过 3 族强调色就报警。

## 深度来自色调分层，不来自阴影

用 `surfaceContainerLow/High/Highest` 分层；真阴影只留给真正浮起来的东西（菜单、对话框、拖拽中的元素）。
**检测**：把阴影全删掉，层级还成立吗？应该成立。

## 用留白分隔，不用分割线

每行之间一条 divider = 表格，不是 UI。
**检测**：`grep -c "HorizontalDivider" src/`——大多数都能换成 spacing。

## 一种圆角语言，一种描边语言

圆角半径混用、图标描边粗细不一，是"拼装感"的最快来源。从 shape scale 里选，图标只用一套。
**检测**：trace 一张截图，对比各卡片圆角。

## 动效必须有意义

每个动画都要能回答"它帮用户理解了什么"——从哪来、到哪去、输入已收到、工作进行中。答不上来的动画是噪音。
**检测**：把屏幕上每个动画的意义说出口。说不出的，删掉。

## 全应用一套编舞

一次决定：谁动、从哪动、到哪去、什么顺序。然后永不在单屏即兴发挥。`MotionScheme` 自动约束原生组件，自定义动效与之保持一致。
**检测**：用户能用一句话描述你应用的动效风格吗？

## 重点可度量（有研究背书）

M3 Expressive 研究（46 项实验，约 1.8 万参与者，眼动追踪）发现：重点放对时，用户定位关键元素快至 4 倍。杠杆在重点放哪，不在有多少：主操作应在**位置、尺寸、颜色**上同时胜出。
**检测**：第一眼看屏，能不扫视就找到主操作吗？

## 护栏：表现力不许牺牲熟悉感

同一份研究：把纵向列表拆成散乱的无标签瓷贴、去掉操作的文字标签，"现代感"上升但可用性暴跌。所以：

- 通过形状、颜色、动效、重点表达。**不**重造结构——纵向列表、轮播、底部导航是承重墙。
- 关键操作永远图标 + 文字标签。
- 强度匹配领域：银行应用冷静精确，相机/媒体应用可以活泼。表现力是旋钮，不是开关。
- 密度跟随内容：数据密集工具就该比消费信息流更紧凑。
